# Автоматическое продление service manifest

Workflow `Renew service manifest` запускается ежедневно в 05:23 UTC и вручную
через Actions → Run workflow (только main). При остатке срока не более трёх дней
он увеличивает sequence, выставляет сроки 7/29 дней и подписывает manifest.
Адреса, маршруты, веса и URL обновлений не меняются.

Repository Actions Secrets:

- `VOXO_MANIFEST_SIGNING_KEY`: приватный Ed25519 PEM, соответствующий текущему
  keyId в public/service-manifest-public-keys.json.
- `VOXO_MANIFEST_PUSH_TOKEN`: fine-grained token пользователя voxo-app, только
  этот репозиторий, Contents: Read and write. Продлевать до истечения токена.

Ключ доступен только шагу подписи, временный файл удаляется при завершении шага.
Workflow не запускается на pull request. GITHUB_TOKEN имеет только Contents: read.
Публикация проверяет аккаунт, author/committer и список изменённых файлов, затем
выполняет обычный push без force/rebase. При конкурирующем ручном изменении push
отклоняется: повторный запуск читает актуальный main и сохраняет его настройки.
После push проверяются commits/contributors API и анонимная загрузка manifest
по фактическому URL клиента, включая подпись и соответствие ожидаемому payload.

Проверка Verify service manifest продолжает отклонять просроченную конфигурацию.
Автоматическое продление сначала проверяет старую подпись, разрешая старый срок
только на этом входном шаге; результат обязательно проверяется без исключения.

Следить за failed runs и сроком токена. В публичных репозиториях GitHub может
отключить расписание после 60 дней отсутствия активности; расписание также может
задерживаться. Коммиты продления поддерживают активность, но Actions не является
независимым мониторингом: при сбое требуется ручной запуск/устранение причины.

Для контрольной проверки подписи и реального push при ручном запуске включить
`force`. Плановые запуски всегда сохраняют порог в три дня. Аккаунт токена
проверяется и при свежем manifest.
